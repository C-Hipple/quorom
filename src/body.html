    Put a feature before the council

    Describe a feature for an existing software project, then paste in whatever the council should work from, like product requirements, how the system works today, constraints or relevant code. Three builders propose implementations, the council votes, and the Chair writes the implementation plan.

      Or start from an example: two-factor sign-in, CSV export for reports, or live comment notifications.

      Who sits in the chamber

      Builders

      • A

        The Pragmatist looks for the smallest change that fits the existing code, reusing what the project already has.

      • B

        The Visionary looks for a better design than the obvious one, while keeping it buildable.

      • C

        The Architect fits it to the system's structure, with a sound data model and clean interfaces.

      Council

      • The Advocate speaks for the users and checks each proposal against the requirements.

      • The Skeptic looks for what could break: regressions, security, performance and hidden complexity.

      • The Strategist weighs effort and risk against the payoff, and how the work can ship in steps.

      Chair

      • The Chair counts the ranked ballots and writes the implementation plan from the winning proposal, borrowing the best of the rest.

      Final review if you ask for it

      • The Scaling Reviewer checks how the plan holds up as usage grows: load, data volume, queries, queues and cost.

      • The Security Reviewer checks the plan for security and privacy: access, data exposure, injection, secrets and abuse. The Chair then revises the plan to address both reviews.

      A session makes seven requests: three proposals, three reviews and the plan. The council's questions add up to twelve more, three councilors questioning each proposal and each builder answering, and the final review three more. Each role runs on the agent you choose, so the builders can draft on a fast, cheap model while the council and the Chair decide on a frontier one. Inside claude.ai the agents run on Claude. Run with bun start, every seat can be an agent working inside your project folder, on Claude Code, OpenRouter or another OpenAI-compatible service, and Quorum can also use Hermes Agent.

      2Questions

      As each proposal comes in, each councilor asks its builder about what it leaves open: edge cases, missing requirements and technical debt. The builder answers and adjusts the proposal, and the council votes once all three are settled.

      2Council review

      Each councilor reads the three proposals without knowing who wrote them, each in a different order, then ranks all three.

      3The vote

      A first-place ranking earns 3 points, second place 2 and third place 1. A tie goes to first-place votes, then to combined scores, then to the Chair.

      4Final review

      Before the plan is final, one reviewer checks how it holds up as usage grows and another checks its security and privacy. The Chair then revises the plan to address what they find.

      4Final plan

      The plan before the final review

      Ask about anything in the plan, or add what the council should know. The builders revise their proposals with your input, the council votes again, and the Chair answers you in a revised plan.

      Providers

      Claude Code

      Seats on Claude Code run inside the project folder, signed in as you are in Claude Code, and read the project's CLAUDE.md. They can read and search the project's files, and can't change them, run commands, reach outside the folder or use your MCP servers.

      OpenRouter

      Seats on OpenRouter run as agents on Quorum's server, inside the project folder, and read the project's AGENTS.md. They can read and search the project's files, and can't change them, run commands or reach outside the folder, so their model has to support tool calling. Create a key at openrouter.ai/keys. Requests are billed to your OpenRouter account, and the model fields suggest what OpenRouter offers.

      Hermes Agent

      Other OpenAI-compatible endpoint

      Any service that speaks the OpenAI chat completions format with tool calling, such as Ollama, LM Studio, vLLM or LiteLLM. Its seats run as agents on Quorum's server, inside the project folder, the same way as OpenRouter's, and the server is what calls the service.
